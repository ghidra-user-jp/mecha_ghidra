# 共有キャッシュの接続先照合と実機検証（2026-09-21）

継続レビューで、共有リポジトリ用の既存キャッシュを再利用する際に、リポジトリ名だけを照合し、サーバーとポートを照合していない問題を修正しました。

## 問題と修正

`ProjectHandle.create_repository_cache_project()` に、`old-server:13100/shared` の接続情報を持つキャッシュと `ghidra://new-server:15100/shared` を渡すと、従来は `status=exists` と新しいURLを返していました。実際のキャッシュの接続先は変更されていないため、呼び出し元が指定した接続先とは異なります。この処理はBSimのリモート一致結果を読み込むためのキャッシュ作成でも使用されます。

再利用時には、保存された `SERVER`、`PORT_NUMBER`、`REPOSITORY_NAME` を指定先と照合します。不一致なら既存の `PROJECT_ALREADY_EXISTS` エラーを返し、キャッシュを書き換えません。ホスト名の大文字小文字・末尾のDNSルートドットと、Ghidraが同じ接続先として扱う既定ポートの表記差は受け入れます。Ghidraの `DefaultProjectData` と `ClientUtil` の同梱ソースで、保存形式と非正ポートの既定値13100への変換を確認しました。

製品の変更は `project_handle.py` の1ファイル、追加テストは `test_repository_cache_identity.py` の10件です。非推奨API、外部ライブラリの非公開APIへのパッチ、スクリプトのSHA-256計算は追加していません。

## 修正の検証

- 修正前: **4 failed / 6 passed**。別ホスト、別ポート、その両方、ポート省略キャッシュに対する別ポート指定の4条件で誤った再利用を再現。
- 修正後: キャッシュ・ProjectHandle・BSim・ターゲットサービスの関連テスト **201 passed**。
- 一時Ghidra Serverから実際の共有キャッシュを作成し、同じ接続先は再利用、別ホスト・別ポートは拒否されることを検証。検査前後で `project.prp` は同一。
- 通常テスト全体: **1,599 passed / 215 skipped**（Python 3.12.11、102.49秒）。

一括実行の1失敗は `GHIDRA_RUNTIME_SHARED_PROJECT_LOCATION` 未設定によるものでした。その後、localhost限定の使い捨てGhidra Server、テスト専用ユーザー・リポジトリ・キャッシュを作成し、共有同期テストを完走しました。チェックアウト、コミット、履歴、差分、複数キャッシュ間の同期、取り消し、削除ガードを既存テストで確認しています。終了後のサーバープロセス停止も確認しました。

サーバーの最初の起動では、自動証明書生成待ちとテスト用証明書のKey Usage不足がありました。設定を修正した最後の起動で上記テストが成功しています。これらはテスト環境の準備段階の失敗として、製品のテスト失敗と区別して記録しています。

BSimは一時H2データベースに検証用バイナリのシグネチャを登録し、内容を一部変えてMD5を変えた別ファイルから類似検索しました。既存のBSimデータベースや共有Ghidra Serverは使用していません。H2での成功はPostgreSQL／Elasticsearch固有の接続や認証の検証を意味しません。

一括実行は今回のキャッシュ修正前に開始しました。修正したキャッシュ処理はその後の関連201件と実Ghidra Serverで検証しています。スクリプト・インポート・保存・データ型など、それ以外の188個のPythonソース・テストファイルは今回変更していません。

## 配布物と残る環境差
