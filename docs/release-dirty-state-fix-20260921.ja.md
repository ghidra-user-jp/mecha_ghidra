# 未保存状態の判定に関するレビュー・修正（2026-09-21）

リリース前レビューを継続し、変更を残さない操作でも変更済みとして記録する問題を修正しました。

## 再現した問題

`RuntimeCoreExecution.call()` は、編集権限が必要なコマンドが正常に戻ると、その結果や実際の変更状態にかかわらず `dirty_programs` に追加していました。

隔離した実Ghidraで次の6ケースを再現しました。すべて `Program.isChanged() == false` なのにランタイムの変更済みフラグがtrueになり、その後の `save_project_program` が不要な保存を実行しました。

- 既存の関数に対する `create_function`
- 解析済みプログラムに対する `analyze_program(force=false)`
- Undo履歴がない状態での `undo_program_change`
- `apply_edits(dry_run=true)`
- 失敗して全件ロールバックした `apply_edits`
- 最後の未保存編集を `undo_program_change` で戻した状態

このフラグは共有プロジェクトの `modified_since_checkout` / `can_checkin` の補正や同期前の変更判定にも使われるため、保存対象や同期状態を誤認する原因になります。共有サーバーそのものには接続せず、同期状態の補正は実Programとリポジトリ情報のテスト用置換を組み合わせて検証しました。

## 修正

コマンド実行後に、公開APIの `Program.isChanged()` から未保存状態を更新します。変更が残らない操作はフラグを立てず、最後の変更をUndoした場合はフラグを解除します。既存の未保存編集がある場合は保護を維持します。状態取得が例外で失敗する場合も、保存すべき変更が失われないよう既存の保護方針を維持します。

共有プロジェクトでは「保存は完了したがDomainFileの同期状態にまだ反映されていない変更」を別に記録します。この状態は、何もしない操作や追加編集のUndoだけでは解除しません。保存後の同期状態の確認・再読み込み・セッション終了など、既存の変更記録を解除する処理で一緒に破棄します。

この区別は既存の保存・コミット処理を保持するために必要です。最初の修正案で未保存状態だけを見てフラグを解除すると、保存→何もしない操作→コミットの追加回帰テストが失敗しました。そのケースも修正し、同期への反映待ちを取り消さないようにしています。

## 検証範囲

`tests/test_runtime_dirty_state.py` に実Ghidraの16ケースを追加しました。

- 未変更・未保存編集ありの各状態で、既存関数の作成、解析済みプログラムの解析、プレビュー、全件ロールバック、読み取りだけのPyGhidraスクリプトを実行
- Undo/Redoの履歴なし、実編集→Undo→Redo→保存・再読み込み
- 非atomicな編集が一部成功した後の保存・再読み込み
- 失敗してロールバックするPyGhidraスクリプトと既存編集の保持
- Programの状態、ランタイムのフラグ、`get_program_info`、同期状態の表示、保存の有無の整合性

通常テストには、実際の変更状態に基づく追跡、状態取得失敗時の保護、同期状態の表示、保存後の反映待ちの保持、ターゲット単位の後始末を追加・更新しました。

| 検証 | 結果 |
| --- | --- |
| 通常テスト全体の最終実行 | **1,589 passed / 215 skipped**（146.54秒） |
| 変更追跡・同期・ライフサイクル・セッション管理 | **230 passed**（1.30秒） |
| 実Ghidraの最終実行 | **42 passed**（110.45秒） |
| Ruff check / format check | **189ファイル成功** |
| `git diff --check` | 成功 |

実Ghidraの42件は今回追加した16件と、ツール・スクリプトの既存回帰26件です。通常実行でスキップされる実機テストは別実行で確認しており、215件全体の実行成功を意味しません。

変更前の実機探索は7失敗・1成功でした。このうち6失敗が上記の製品不具合、1失敗は探索側がスクリプトサービスを初期化していなかったためです。新規実機テストの初回にも、廃止済みの単独コメントツールを呼ぶ／スクリプト初期化を省くテスト設定ミスがあり、既存の `apply_edits` と起動手順へ合わせました。探索・途中結果を最終成功結果と区別して検証資料に保持しています。

Ghidra 12.1.3 / Java 21 / macOS arm64の専用JVMと一時プロジェクトを使用し、`MCPDeprecationWarning` をエラー化しています。外部共有リポジトリへの保存・コミット、BSimサーバー、Docker・他OSの検証結果を示すものではありません。

製品の変更は、状態コンテナ、コマンド実行、セッションの変更追跡、保存後の状態処理の4ファイルです。非推奨APIや外部ライブラリへのパッチは追加していません。

[検証資料](release-dirty-state-fix-evidence-20260921.zip)に、変更前のスナップショット、今回の差分、テスト、再現入力と結果、実行条件、ログ・JUnit XMLを保存しています。
