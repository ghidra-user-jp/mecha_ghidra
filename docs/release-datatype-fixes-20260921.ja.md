# 構造体のoffset配置と列挙値の一括置換の修正（2026-09-21）

[前回のデータ型レビュー](release-datatype-review-20260921.ja.md)で確認したP2の2件を修正しました。

## 修正内容

### 構造体の明示offset配置

`create_struct` と `add_struct_members` で、明示offsetにメンバーを配置する前に、必要なサイズまで末尾を拡張します。サイズを省略した空の構造体へのoffset 0配置、末尾への追加、未定義領域を挟んだ配置を扱えます。既存フィールドの位置をずらさず、offset省略時の末尾追加も維持します。

両ツールで共通の配置処理を使用し、Ghidraの公開API `growStructure()` と `replaceAtOffset()` を呼びます。Ghidraは空の構造体でも `getLength()` に1を返すため、公開API `isZeroLength()` で空の実サイズを判定します。サイズ確保済みの場合は拡張しません。

負のoffsetは拒否します。途中まで構造体を拡張した後に不正なメンバーを検出した場合も、既存のトランザクションで元の定義に戻します。

### 列挙値の一括置換

`set_enum_values` は、削除対象と置換対象の既存値をすべて除去した後、新しい値を追加します。置換前の符号付き／符号なしの値が途中で残ることによる、JSONのキー順への依存を解消しました。

変更対象外の値とコメントを維持し、明示削除と置換が同じ名前を指定した場合は新しい値を設定します。前後の空白を除いた名前が重複する場合も、最後の指定を使用します。最終状態が残す値と矛盾する場合は、削除済みの値を含めて元のenumへ戻します。

非推奨API、外部ライブラリの非公開API、ハッシュ計算は追加していません。MCPツールの入力形式も変更していません。
