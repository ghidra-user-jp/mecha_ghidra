# スクリプトツールの修正と検証（2026-09-20）

`run_script` の実行待ちに設定時間を適用し、ユーザーの指定に従ってスクリプトのSHA-256計算と整合性検査を撤去しました。

## 変更内容

- スクリプト実行と共有同期の排他バリア取得にも `--lock-timeout-seconds` を適用。待機時間を超えた要求は `LOCK_TIMEOUT` を返し、後から実行されません。
- スクリプトのSHA-256計算、ファイルのハッシュ一覧、実行前の整合性検査、`expected_sha256` 引数、情報・実行結果の `sha256`、`SCRIPT_SNAPSHOT_CORRUPT` を削除。
- `catalog_revision` はカタログ構築ごとのランダムな識別子に変更。
- 起動時の私有スナップショットと子スクリプト用ファイルのコピー、インラインの一時配置・後片付けを維持。
- プログラムの `expected_revision`、トランザクション、ロールバック、実行状態が不明なターゲットの隔離を維持。
- 日本語・英語のツール説明、設定ドキュメント、CLIヘルプを更新。

今回削除したのはスクリプト内容に関するハッシュ処理です。解析対象バイナリのハッシュ、結果キャッシュの識別子、依存・配布物の検証処理は対象外です。

## 検証結果

| 検証 | 結果 |
| --- | --- |
| 修正前の待機時間回帰テスト | reader/writer × スクリプト/同期の4ケースが、待機上限を超えて失敗 |
| 修正後の関連単体テスト | 110 passed |
| 通常テスト全体 | 1,468 passed / 99 skipped |
| 実Ghidraのスクリプトテスト | 62 passed / 0 skipped |
| Ruff / フォーマット / `git diff --check` | 成功 |

通常・実機テストはMCPの非推奨警告をエラーとして実行しました。実機環境はmacOS arm64、Python 3.12.11、Temurin Java 21、Ghidra 12.1.3、Jython拡張ありです。専用JVM設定と一時プロジェクトを使用しました。

追加の実機ケースで、待機上限を超えたスクリプトがプログラムを変更せず、一時ファイルも残さず、ロック解放後に再試行できることを確認しました。また、コピー元の親・子スクリプトを編集しても起動時コピーを実行することと、古い `expected_revision` を引き続き拒否することを確認しました。3言語間の子スクリプト呼び出しでは、成功結果と失敗詳細の双方から `sha256` がなくなったことも検証しています。

通常テストの99件のスキップは実機・外部環境向けです。そのうちスクリプトの62件を今回別途実行しました。Docker、Windows/Linux、外部共有リポジトリ・BSimの実行検証や公開処理は今回の範囲に含みません。既存のMCPサーバーも再起動していません。
