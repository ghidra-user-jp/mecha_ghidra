## file_offset指定時の長さ省略

rawインポートで `file_offset` が指定され、`length` が省略された場合は、ファイルサイズからオフセットを引いた長さをローダーに渡します。明示された長さは維持します。計算結果が0以下になるファイル末尾以降のオフセットは、インポート前に `VALIDATION_ERROR` で拒否します。

10バイトのファイルをオフセット4から取り込むケースでは、末尾にゼロを追加せず、元の残り6バイトだけを保存する回帰テストを追加しました。明示的な長さ2・6、オフセット0も検証し、保存後のサイズと全バイトが一致することを2回の開閉で確認しました。

## 明示エントリアドレスの単位

`entry_address` は言語のアドレス単位で解釈し、公開API `AddressSpace.getAddressableUnitSize()` でバイトオフセットに変換してから、既存の範囲検査とJava long変換を通します。`entry_offset` は引き続きバイト単位です。

PICの回帰テストでは、ベース `CODE:1000` に対し、`entry_address=0x1001` と `entry_offset=2` の両方で2命令目の `CODE:1001` に関数とエントリが作られることを確認しました。16進・10進・8進・2進表記と、保存後の2回の開閉を検証しました。既存のx86の低位・上位64ビットアドレス、範囲外指定の回帰テストも成功しました。

## 空の検索一致からの再開

カーソルから再開した際は、最初の一致が前回返した空の一致と同じ位置・範囲である場合だけ除外します。消費した文字を一致範囲から除外する `\K` により、別の一致から再開した場合はその一致を返します。

MCP SDK 2の実クライアントで、`a\K`、先読み `(?=a)`、空の選択肢 `|a` を1件ずつ取得する12ケースを追加しました。`count_mode=bounded/none` と応答上限1024・12000文字を組み合わせ、欠落・重複なく終了すること、boundedの残件数、応答サイズ、出力スキーマとテキスト・構造化結果の一致を確認します。直接呼び出しのテストにも `a\K` と `a\K|` を追加しました。
