## P2: BSim参照検証に失敗しても、ターゲットの読み込み状態が残る

対象: `src/ghidra_mcp/application/services/bsim_service.py:1200–1206`

`bsim_load_matched_executable` は、先に `create_session()` でターゲットを登録してプログラムを開き、その後で `_validate_loaded_match()` によるMD5・ドメインパス・関数エントリの検証を行います。ここで `BSIM_MATCH_STALE` になっても、作成したセッションの破棄や、元のターゲット登録の復元がありません。

古いBSim参照を使用した際、呼び出しは失敗したと通知されますが、次の状態が残ります。

- 新規ターゲット: 失敗した読み込みで開いたプログラムを保持し続ける。
- 未ロードの既存ターゲット: 元のプロジェクト参照が、失敗した読み込み先のプロジェクトに変わる。

後者では、利用者が失敗前のプロジェクトを指していると考えて後続ツールを呼ぶと、別のプログラム／プロジェクトへ操作が向く可能性があります。

### 実Ghidraでの再現

1. 空の `original` プロジェクトと、`/tiny.bin` を格納した `sample` プロジェクトを作成する。
2. ターゲット `candidate` を `original` に登録し、プログラムは未ロードのままにする。
3. `sample:/tiny.bin` を指す `matched_ref` で `bsim_load_matched_executable(target="candidate", ...)` を呼ぶ。
4. 参照のMD5を実プログラムと異なる値にする、または関数エントリのない `0x1001` を指定し、`BSIM_MATCH_STALE` を発生させる。
5. `list_targets` で状態を比較する。

```text
前: candidate → original, domain_path=null
結果: BSIM_MATCH_STALE
後: candidate → sample, domain_path=/tiny.bin
```

新規ターゲットでも、失敗後に `candidate → sample:/tiny.bin` が残りました。MD5不一致／関数エントリ不一致 × 新規／登録済みターゲットの **4条件すべてで再現**しています。

正常な参照では新規・登録済みの両方で読み込みが成功します。また、呼び出し前からロード済みのプログラムを検証して失敗する場合、その既存プログラムを維持する挙動は正常でした。

### 修正方針

参照検証までを読み込みの成功条件に含め、失敗時は、この呼び出しが新たに開いたセッションを破棄して、呼び出し前のターゲット登録を復元します。既存のロード済みセッションを検証しただけの場合は、それを閉じないよう区別する必要があります。
