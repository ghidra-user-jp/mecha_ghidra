# スクリプトの残存スレッド監視2件の修正（2026-09-20）

[前回のレビュー](release-continuation-review-20260920.ja.md)で確認したP2の2件を修正しました。

## 変更内容

### 隔離情報を更新しても残存スレッドを保持する

`HeadlessContext.mark_execution_invalid()` は、既存の隔離情報を引き継ぎ、新しい情報を統合します。JavaスレッドはID、PythonスレッドはThreadオブジェクトに対応するtokenで重複をまとめます。PythonのOSスレッドIDが再利用されても、別のワーカーの記録を失いません。更新をロック内で行い、スクリプト実行側とTransactionListenerから同時に報告されても記録を保持します。

これにより、残存スレッドが後からトランザクションを開始して隔離理由が変わっても、`close_session(discard_changes=true)` は既存の生存確認を行います。スレッドが生存中はcloseを拒否し、終了後にはcloseできます。close側に新しい検査は追加していません。

### インスタンス生成前からスレッドを監視する

`execute_script()` のJavaスレッドスナップショットとPythonスレッド開始の記録を、`provider.getScriptInstance()` より前に移動しました。Javaのコンストラクターとstatic初期化子で開始したスレッドも対象になります。

ロード・初期化に失敗した場合もスレッド観察結果をエラー詳細に添え、外側のトランザクション処理が隔離の要否を判定します。ロードエラーの分類と原因は保持し、トランザクションをロールバックします。Jythonインタープリターの後片付けとPythonのThread.startの復元も行います。

Jythonなどの共通ランタイム初期化は観察開始前に完了させ、既存のGhidra/OSGi内部スレッドの除外を維持します。スナップショット回数やスタック取得は増やしていません。今回の修正で非推奨APIや外部ライブラリの非公開APIへの依存は追加していません。
