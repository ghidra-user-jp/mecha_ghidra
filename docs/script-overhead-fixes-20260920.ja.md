# スクリプト機能の過剰処理4件の修正（2026-09-20）

[前回のレビュー](script-safety-overhead-review-20260920.ja.md)で挙げた4件を修正しました。

## 変更内容

| 対象 | 修正後の動作 |
| --- | --- |
| マニフェスト付きルート | `META-INF/MANIFEST.MF` の存在だけでは除外せず、一覧・実行の対象にする。Ghidraの通常のロード・コンパイル処理に委ねる |
| 共有デコンパイラー | 正常終了、`transaction_outcome=unchanged`、実行状態が正常、プログラムrevisionも同一の場合は維持する。編集・ロールバック・異常終了・revision取得失敗では無効化する |
| Javaスレッド監視 | `ThreadMXBean.getAllThreadIds()` でIDを列挙し、新しいIDの名前・daemon属性だけを `getThreadInfo(ids, 0)` で取得する。スタックは取得しない |
| 出力捕捉 | 残り保持容量分だけJava配列にコピーする。超過分はByteBufferの位置を進めて消費し、破棄数を加算する。満杯なら配列確保・bytes変換を省く |

デコンパイラーを維持する場合も、インライン用バンドルの除去とトランザクション監視の再設定は実行します。スレッド検知は従来どおりプラットフォームスレッドと記録したPythonスレッドを対象とするbest-effortの検知です。Java 21の同梱ソースで、今回使用したThreadMXBeanのAPIが公開APIであり非推奨指定がないことと、深さ0ではスタックを採取しないことを確認しました。

出力の保持容量・破棄数は同じロック内で更新します。部分的に保持する場合も、捨てる末尾はコピーしません。UTF-8の文字の途中で上限に達した場合の置換表示は従来どおりです。
