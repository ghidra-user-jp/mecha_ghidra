# インポート範囲と検索継続の修正（2026-09-21）

[前回のレビュー](release-result-review-20260920.ja.md)で確認したP2の2件を修正しました。

## rawインポートの範囲外アドレスを拒否

`ProjectHandle._resolve_binary_loader_args_locked` で、既存のローダーオプション解決時に選択した言語のデフォルトアドレス空間を取得し、`base_address` が最小・最大の範囲内にあるかを確認します。アドレス表記がアドレス単位、Ghidraのオフセットがバイト単位である点も考慮しています。

範囲外の指定は `ProgramLoader.load()` と保存の前に拒否し、製品ツールでは既存の `VALIDATION_ERROR` として返します。0番地と有効な上位64ビットアドレスは引き続き使用できます。言語・アドレス取得には公開APIを使用し、非推奨・非公開APIを追加していません。

回帰テストでは、32・64ビットそれぞれの負値、上限超過、0番地、最大アドレスを検証します。拒否時にプログラムが保存されていないこと、同じファイルを正しいアドレスで再インポートできること、保存したプログラムを2回開閉して配置とリソース解放を維持することまで確認しています。既存の数値表記・上位64ビット・エントリ指定の回帰テストも実行しました。

## 検索応答を縮めても一致位置とカーソルを保持

`_search_stored_result` では、通常の応答が上限に収まる場合はそのまま返し、件数を減らしても収まらない場合は、1件の一致位置・長さ・必要な継続カーソルを確保します。そのうえで表示用パターンと一致文字列の長さを二分探索で調整します。

固定の300文字の余白と80文字の一致文字列という見積もりを撤去し、MCPのテキストと構造化結果の両方を含む応答サイズで判断します。表示を省略しても元の一致位置・長さを保持し、`pattern_truncated` / `match_truncated` で省略を示します。既存の1024文字の取得ツール最小上限は維持しています。

MCP SDK 2の実クライアントを使う回帰テストを36ケース追加しました。応答設定1・1024・12000文字、`count_mode=bounded/none`、コンテキスト統合の有無、400文字のリテラル・512文字のNUL・空文字列への一致を組み合わせ、全一致を重複や欠落なく最後まで取得できること、応答サイズ・出力スキーマ・両結果チャネルの一致を検証します。バックエンド解析は使用せず、製品の結果キャッシュに格納したテキストを製品のMCP検索ツールで取得する検証です。
