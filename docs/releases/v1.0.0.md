# Mecha Ghidra v1.0.0

Mecha Ghidra 1.0 provides a standalone, headless Ghidra MCP server for AI-assisted binary analysis and sharing findings with human analysts through Ghidra Server.

## Highlights

- **Script execution:** run Java, PyGhidra, and Jython scripts against the loaded program, including inline source, diagnostics, captured output, and transaction outcomes. Enable the category with `--add-category scripts` or `--tool-profile full`. Jython requires the matching Ghidra extension.
- **MCP SDK 2.2.0:** the lockfile pins the tested SDK version. Stdio and stateless Streamable HTTP use the SDK's public APIs, explicit schemas, structured results, and worker-thread dispatch.
- **Analysis and editing:** consolidated function and reference queries, bounded `batch_read`, and `apply_edits` for related annotation changes. The complete catalog contains 80 tools; the default profile exposes a smaller selection.
- **Reliable project state:** fixes for import address/range handling, program and decompiler cleanup, dirty-state tracking, packed structure edits, BSim result limits, and shared-cache repository identity checks.
- **Large results:** paged retrieval and search preserve actionable continuation information within the configured response budget.

## Upgrade and installation

The Python distribution and executable are now named **`mecha_ghidra`**. Replace the old `ghidra-mcp` command in MCP client configuration, run `uv sync --frozen`, and refresh the client's tool schemas. See the [upgrade guide](https://github.com/ghidra-user-jp/mecha_ghidra/blob/v1.0.0/docs/troubleshooting.md#upgrading) for renamed tools, response changes, and Docker migration.

For a reproducible checkout:

```sh
git clone --branch v1.0.0 https://github.com/ghidra-user-jp/mecha_ghidra.git
cd mecha_ghidra
uv sync --frozen
```

Then follow the [local setup](https://github.com/ghidra-user-jp/mecha_ghidra/blob/v1.0.0/docs/usage.md#local-setup) or [Docker guide](https://github.com/ghidra-user-jp/mecha_ghidra/blob/v1.0.0/docs/docker.md). This release is distributed through GitHub; it is not published to PyPI.

Script exception propagation requires the PyGhidra snapshot pinned in `pyproject.toml` and `uv.lock` at upstream commit `263160cf57db21a9e25f1e0a8bc42fde5b8824eb`. It identifies itself as 3.2.0 but is not a stable upstream release. Use the documented `uv` or Docker installation so the pin is honored. See the [dependency explanation](https://github.com/ghidra-user-jp/mecha_ghidra/blob/v1.0.0/docs/development.md#pyghidra-dependency-and-script-failures).

## Release assets

- **`mecha_ghidra-1.0.0.tar.gz`:** the Python source distribution built from this tag.
- **`ghidra_12.1.3_decompiler_natives_all.zip`:** a complete Ghidra 12.1.3 distribution with native decompiler and Sleigh binaries added for Linux ARM64, Apple Silicon, and Intel Mac.
- **`ghidra_decompiler_natives_all.zip`:** those native binaries as an overlay for an existing Ghidra 12.1.3 installation. Extract it at the installation root. The added paths are `Ghidra/Features/Decompiler/os/linux_arm_64/`, `mac_arm_64/`, and `mac_x86_64/`.

The native ZIPs reuse the verified archives pinned in [release configuration](https://github.com/ghidra-user-jp/mecha_ghidra/blob/v1.0.0/scripts/ghidra_release.env). They include upstream license notices; the Mecha Ghidra Python package uses Apache-2.0.

## Execution boundaries

Scripts execute with the server process's OS privileges. Cancellation is cooperative, and Program transactions do not undo filesystem or network side effects. Script execution takes a process-wide exclusive lock. This release does not add a worker pool, automatic assignment of subagents, or a unified endpoint for parallel script workers.

Ghidra Server shares saved program versions through checkout/check-in; headless conflict merging is unsupported. Separate Mecha processes must use separate local project caches. A 100-sample, four-agent batch deployment has not been validated as part of this release.

## Validation

The final local tool review recorded **1,627 passing ordinary tests** and separate successful executions covering **all 219 opt-in runtime cases**, including Java/Jython/PyGhidra scripts, disposable Ghidra Server synchronization, H2 BSim, and stdio/HTTP. Runtime results were collected across multiple runs, not one all-inclusive invocation. See the [tool review and evidence](https://github.com/ghidra-user-jp/mecha_ghidra/blob/v1.0.0/docs/release-tool-by-tool-review-20260921.ja.md).

The final runtime review used macOS ARM64, Ghidra 12.1.3, and Java 21. Docker Linux ARM64 has an earlier validation record in this release branch. Windows, Linux AMD64 runtime behavior, and external PostgreSQL/Elasticsearch were not validated by that final review. GitHub Actions checks the release candidate separately.
